# ИНСТРУКЦИЯ ПОЛЬЗОВАТЕЛЯ (Пошаговое руководство)

## 0. ВВЕДЕНИЕ 
* **Название проекта:** FileSorter
* **Ссылка на работающий MVP:** https://github.com/m-zhiltsova/FileSorter.git
* **Для кого этот продукт:** Для разработчиков, системных администраторов и DevOps-инженеров, которые хотят автоматизировать рутину по очистке дисков и сортировке файлов на Linux-машинах.
* **Что он делает:** Это консольная утилита, которая по заданным правилам автоматически раскладывает файлы по папкам и безопасно отправляет старые логи/бэкапы в корзину или архив.
* **Сколько времени займёт знакомство:** 10 минут до первой успешной автоматической очистки.

## 1. ПЕРВЫЙ ВХОД В ПРОДУКТ
* **Как попасть в продукт:**
  Откройте терминал (консоль) в вашей Linux-системе, склонируйте репозиторий или скачайте архив с релиза.
* **Что нужно сделать на старте:**
  1. Установить системную утилиту `trash-cli` (для безопасного удаления) и Python-библиотеку `pyyaml`.
  2. Запустить скрипт-мастер для генерации конфигурации.
* **Что пользователь увидит первым:**
  Интерактивное меню в терминале, которое пошагово спросит, какие папки сканировать и какие правила применить.

## 2. ОСНОВНАЯ ФУНКЦИЯ №1: АВТОМАТИЧЕСКАЯ СОРТИРОВКА
Описание самой важной функции MVP — той, ради которой продукт существует.

* **Название функции:** Раскладка файлов по категориям (папкам) на основе их расширений.
* **Зачем она нужна пользователю:** Закрывает боль хаоса в папках `Downloads` или `Projects`. Больше не нужно вручную искать, где лежит нужный `.jpg` или `.log`.
* **Пошаговая инструкция:**
  1. Пользователь добавляет правила сортировки в `config.yaml` (например, `.log` -> `Logs`).
  2. Затем запускает команду с флагом `--dry-run`, чтобы увидеть план.
  3. Система сканирует папки и показывает, какие файлы будут перемещены.
  4. Пользователь убирает `--dry-run` и получает отсортированные файлы.
* **Пример входных данных:** Папка `/home/user/downloads` с файлами `report.pdf`, `photo.jpg`, `server.log`.
* **Пример результата:** Файлы лежат в `/home/user/downloads/Images/photo.jpg` и `/home/user/downloads/Logs/server.log`.

## 3. ОСНОВНАЯ ФУНКЦИЯ №2: БЕЗОПАСНАЯ ОЧИСТКА
Описание второй ключевой функции из ТЗ.

* **Название функции:** Удаление старых файлов в корзину (`trash`) или перенос в архив (`archive`).
* **Зачем она нужна:** Освобождает место на диске без страха безвозвратно потерять данные (в отличие от `rm`). Файлы старше N дней автоматически убираются с глаз.
* **Пошаговая инструкция:**
  1. В `config.yaml` укажите `cleanup_rules` с параметром `older_than_days`.
  2. Укажите действие: `trash` (в корзину ОС) или `archive` (в отдельную папку с сохранением структуры).
  3. Запустите `python3 filesorter.py run --config config.yaml`.
  4. Система переместит файлы. Вы сможете восстановить их через стандартную корзину Ubuntu/Debian или найти в папке архива.
* **Пример входных и выходных данных:** 
  *Вход:* Файл `build.log` не менялся 35 дней. Правило: `older_than_days: 30, action: trash`.
  *Выход:* Файл исчезает из папки и попадает в системную корзину (`~/.local/share/Trash/`).

## 4. ОСНОВНАЯ ФУНКЦИЯ №3: АВТОМАТИЗАЦИЯ (CRON)
Описание третьей ключевой функции из ТЗ.

* **Название функции:** Запуск по расписанию через системный планировщик `cron`.
* **Зачем она нужна:** Даёт полную автоматизацию. Пользователь забывает о проблеме забитого диска навсегда — система работает сама.
* **Пошаговая инструкция:**
  1. Откройте редактор crontab: `crontab -e`.
  2. Добавьте строку для запуска каждую ночь в 03:00.
  3. Сохраните файл. Система сама будет подхватывать новые файлы и чистить старые.
* **Пример результата:** Утром вы приходите к компьютеру, а диск уже чист, логи убраны, код рассортирован.

## 5. ЧТО ДЕЛАТЬ, ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
Описание типичных ошибок и способов их решения.

* **Ошибка №1:** `ERROR CONFIG_INVALID: action must be 'trash' or 'archive'`
  → **Что делать:** Вы опечатались в `config.yaml`. Откройте файл и убедитесь, что в `cleanup_rules` указано именно `trash` или `archive` (без опечаток вроде `delete`).
* **Ошибка №2:** `ERROR PATH_NOT_FOUND: Каталог не найден: /home/user/old_folder`
  → **Что делать:** Папка, указанная в `scan_paths`, не существует. Создайте её или удалите эту строку из конфига.
* **Ошибка №3:** `ERROR TRASH_ERROR: trash-cli не найден` или `Permission denied`
  → **Что делать:** 
  1. Если `trash-cli` не найден: выполните `sudo apt install trash-cli`.
  2. Если `Permission denied`: у пользователя, от имени которого запущен скрипт, нет прав на чтение/запись в целевые папки. Проверьте права (`chmod`/`chown`).

## 6. ЧАСТЫЕ ВОПРОСЫ (FAQ)
Ответы на вопросы, которые могут возникнуть у пользователя.

* **Вопрос 1: Я случайно удалил нужный файл в корзину, как его вернуть?**
  → **Ответ:** FileSorter использует системную утилиту `trash-cli`. Файл не удаляется безвозвратно. Вы можете открыть файловый менеджер и найти его в разделе «Корзина» (Trash), либо использовать команду `trash-restore` в терминале.
* **Вопрос 2: Поддерживается ли Windows или macOS?**
  → **Ответ:** MVP ориентирован на Linux (из-за жесткой привязки к `trash-cli` и `cron`). На macOS скрипт может работать, если установить `trash-cli` через Homebrew, но Windows официально не поддерживается в текущей версии.
* **Вопрос 3: Где посмотреть историю всех действий?**
  → **Ответ:** Все операции (успешные и ошибки) записываются в текстовый лог. Он находится по пути `~/.filesorter/filesorter.log`.
* **Вопрос 4: Что будет, если файл с таким именем уже есть в папке назначения?**
  → **Ответ:** FileSorter никогда не перезаписывает файлы. Если возникает конфликт, система автоматически добавит суффикс, например: `report_1.log`, `report_2.log`.
* **Вопрос 5: Как отменить все изменения, если я неправильно настроил конфиг?**
  → **Ответ:** Всегда сначала запускайте скрипт с флагом `--dry-run`. Если вы уже выполнили `run`, файлы, отправленные в корзину, можно восстановить, а перемещенные файлы можно найти через лог `~/.filesorter/filesorter.log`, где записаны старые и новые пути.
